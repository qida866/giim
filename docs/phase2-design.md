# Phase 2 implementation design

Build on the accepted 57-test baseline; preserve all Phase 1 safeguards and bge-m3. Backup: task work/giim-before-phase2.dump. No production data rewrite or replacement.

1. **Coverage first:** version-controlled JSON registry with stable feed ID, canonical publisher/ownership group, country/region of publisher (not presumed event location), language, categories, role, enabled flag, discovery/terms notes. Only reviewed file configuration, no public URL submission endpoint. Validate actual feeds before enabling. Preserve disabled failures and gaps. Fetch with bounded concurrency/response size, public-address validation and redirect revalidation. Persistent health retains last success/failure independently.
2. **Evidence metadata:** add optional source ID and reporting provenance to news JSON metadata, retain publisher canonical identity across feeds/languages, group obvious identical syndicated text as shared evidence without deleting articles. Do not equate audience/language or publisher headquarters with incident location.
3. **Intelligence:** keep conservative candidate geometry. Extend structured generation with claim support review and evidence-backed importance/perspective fields; per-call budgets/caching; unsupported outputs fall back to quoted reporting. No hidden political scores. Deterministic coverage state describes breadth, not truth.
4. **Continuity:** append-only event revisions/timeline snapshots and explicit related-story links only for reviewed same bounded story. Existing article overlap remains the strongest identity signal; disjoint incidents never merge on broad similarity alone. Publication timestamp is reporting time, not asserted occurrence time. New reports and changed claims are exposed without invented timeline timestamps.
5. **Product:** event-first search with source evidence retained; compact region/category navigation labeled by what metadata actually measures; detail coverage, changes, perspectives, fact support and uncertainty. Protected operational API/CLI, no public secrets/errors.
6. **Measurement:** snapshot a broader real corpus separately from live data, label cases/continuity explicitly; evaluate multiple languages, mixed incidents, grounding and reference-event coverage. Report misses and narrow bounds. Inject dependency failures and run repeated/no-op pipeline checks; do not claim long-term uptime from a short soak.

Keep modules small and dependencies unchanged. Each phase has focused regressions and coherent commits; full suite/build/migration/browser validation before final acceptance. Single-host deployment remains; external server/domain access is not a blocker for local work. Source availability does not automatically establish redistribution rights: registry notes retain usage restrictions and production enablement must respect them.

## Implemented continuity and trust boundaries

Continuity is a reviewed edge to an existing stable Event ID, not a topic-wide merge. The candidate must be chronologically newer within seven days, have embedding cosine at least 0.80 against the prior story centroid, and pass an explicit bounded-occurrence/decision comparison with exact identifying quotes on both sides. A broad war, generic actor, or separate meeting is insufficient. Accepted history is preserved across subsequent discovery windows. Clustering continues to see the entire discovery pool so removing preserved story members does not itself change HDBSCAN geometry. A competing partially overlapping candidate aborts publication instead of silently losing evidence.

Event revisions are appended in the same transaction as links and scores. A revision includes the actual reporting URLs/publication times and added/removed report IDs. Observation time is distinct from publication time; neither is labeled occurrence time. Latest summary evidence can cover a newer development while historical reporting stays accessible. No inference that every historical source confirms every latest sentence.

Optional common-fact/perspective fields lacking two independent reporting origins are omitted; exact quote validation and the entailment pass still apply to all retained claims. One failed retained claim blocks the generated output. Complete JSON code fences are unwrapped, but malformed/truncated JSON is not repaired. Entailment is another model judgment and can reject valid paraphrases; it is not independent fact-checking.

The default 20 logical LLM calls reserves up to four for continuity. Accepted unchanged evidence and unchanged source-excerpt fallbacks are cached; unreviewed multi-report candidates can be processed on later bounded runs. Negative/error decisions have short expiry. A fallback is visibly original reporting, has unknown importance/general category, and is not advertised as model-reviewed. Registry poll_minutes is a cadence hint; the existing global 30-minute scheduler remains the actual production cadence.
